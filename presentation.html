12 · SCHEMA / DATA MODEL (2/2) — STAR SCHEMA

The local database as a star

  • Fact = quantity · price · value
  • 5 dimensions: pharmacy · medicine · pharma · illness · date
  • Fast analysis — like our Dashboard
star_query.sql
SELECT p.pharma_name, d.quarter,
       SUM(f.quantity * f.unit_price) AS value
FROM fact_stock f
JOIN dim_pharma p USING (pharma_id)
JOIN dim_date   d ON d.date_id = f.expiry_date_id
GROUP BY p.pharma_name, d.quarter;

18 · ADVANTAGES & LIMITATIONS OBSERVED

What we learned by building it

Advantages

Data stays valid — constraints block bad rows
Powerful questions — JOIN & GROUP BY
No duplicates — one shared catalogue
Fast — under 0.2 s on 20,000+ rows
Cloud — open from anywhere

Limitations

Free hosting sleeps — ~1 min to wake up
One password per pharmacy — no staff roles yet
IDs as MAX + 1 — should be sequences
Schema changes — applied to Neon by hand
Web Stock is US data — prices in $
